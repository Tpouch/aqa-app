# Webhook sortant — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** POST a signed JSON event to one configurable URL (a Hermes webhook route) each time an alert opens or ends, configurable from the web UI and by an API key.

**Architecture:** A one-row `webhook` table (modelled on `notify`). `server/src/webhook.ts` builds the payload (reusing ntfy's French texts), signs it with Hermes' generic V2 scheme and sends it with the same never-throw / 5 s / last-result contract as `Notifier`. The alert timer hands the same events to both senders independently. `/api/v1/webhook` routes accept session or key; key callers get a coarse error.

**Tech Stack:** Fastify 5, `node:sqlite`, `node:crypto` (HMAC), zod 4, React 19, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-24-agent-ia-design.md` (section « PR 2 — Webhook sortant »)

**Branch:** `feat-webhook` from `origin/DEV` **after `feat-cles-api` is merged into DEV** (uses `request.apiKeyId`, `AGENT_RATE_LIMIT`). PR → `DEV`, title `feat(alerts): signed outgoing webhook`.

## Global Constraints

- No new dependency. `types.ts` stays runtime-free. French UI copy, tutoiement.
- Timeout 5 s; never throws to the caller; remote response body never stored or returned.
- Signature (Hermes generic V2): headers `X-Webhook-Timestamp: <unix seconds, bare integer>` and `X-Webhook-Signature-V2: <lowercase hex HMAC-SHA256(secret, "<timestamp>.<raw body>")>`, no prefix. No V1 header (Hermes rejects V1-only).
- Secret mandatory: enable or test without a secret → 422. Secret length 16–200.
- Coarse error for key callers: `"échec : vérifie l'URL et le secret"`.
- No end event when `reason === "disabled"`.

## Review Focus

- Webhook URL that hangs while ntfy is healthy: the ntfy notification still goes out on time → test in Task 3.
- `PATCH /webhook {secret: null}` on an enabled webhook: it must end up disabled, not enabled-without-secret → test in Task 3.
- A remote answering 200 with a huge or HTML body: `ok: true`, nothing of the body stored → covered by Task 2's "corps ignoré" test.
- Key caller reading `GET /webhook` after a session-triggered failure: still coarse → test in Task 3.
- Two alerts opening in the same tick: two separate POSTs, each with its own valid signature → test in Task 2.

### Task 2: Payload, signature and sender

**Files:**

- Test: `server/test/webhook.test.ts` (local `http.createServer` receiver like `fakeNtfy` in `notify.test.ts`, but recording raw body string and headers)

**Interfaces:**
- Consumes: `AlertEvent` with `device_id` (Task 1); `openedMessage`, `closedMessage`, `TEST_MESSAGE`, `networkError` from `notify.ts`; `CATALOG`.
- Produces:
  - `interface WebhookSettings { enabled: boolean; url: string; secret_set: boolean; notify_close: boolean; last: NotifyLast | null }`
  - `type WebhookPayload` = the JSON of the spec: `{ event: "alert.opened" | "alert.closed" | "test"; sent_at: number; text: string; device?: { id; name }; alert?: { kind; label; tone; value; threshold; unit; started_at; ended_at; duration_s; end_value; advice }; url: string }` (`unit` is `CATALOG[kind].unit` or `null` when empty / offline)
  - `payloadFor(e: AlertEvent, publicUrl: string, at: number): WebhookPayload`
  - `testPayload(publicUrl: string, at: number): WebhookPayload`
  - `sign(secret: string, ts: number, body: string): string`
  - `readWebhook(db: Db, opts?: { coarse?: boolean }): WebhookSettings`
  - `const COARSE_ERROR = "échec : vérifie l'URL et le secret"`
  - `class Webhook { constructor(db, opts: { publicUrl; log?; fetch?; timeoutMs? }); send(p: WebhookPayload): Promise<NotifyLast>; alerts(events: AlertEvent[]): Promise<void> }`

`text` = `` `${msg.title}\n${msg.message}` `` of the matching ntfy message. `send` records `last_at/last_ok/last_error` like `Notifier.publish`; without URL or secret it records `"aucune URL configurée"` / `"aucun secret configuré"`. Non-2xx → `HTTP <status>` only.

- [ ] **Step 1: Write the failing tests:**
  - `payloadFor(opened)` (fixture from `notify.test.ts`: Salon, co2_high, 1340 / 1200, started 300 s ago) `toEqual` the spec's example shape: `event: "alert.opened"`, `device: { id, name: "Salon" }`, `alert.label: "CO₂ élevé"`, `tone: "bad"`, `unit: "ppm"`, `duration_s: 300`, `ended_at: null`, `end_value: null`, `advice: CATALOG.co2_high.advice`, `url: "https://x.test/#/alertes"`, `text` starting with `"CO₂ élevé · Salon\n"`.
  - `payloadFor(closed)`: `event: "alert.closed"`, `value: null`, `ended_at: T`, `end_value: 640`, `duration_s: 1380`, `text` = `"Retour à la normale · Salon\nCO₂ élevé : terminé après 23 min, retour à 640 ppm."`.
  - offline opened: `value`, `threshold`, `unit` all `null`.
  - `testPayload`: `event: "test"`, no `device`/`alert` keys, `text` = `"Test · AQA\nLes notifications fonctionnent. Tes alertes arriveront ici."`.
  - `sign("s3cret-s3cret-16", 1700000000, '{"a":1}')` equals `crypto.createHmac("sha256", "s3cret-s3cret-16").update('1700000000.{"a":1}').digest("hex")` and matches `/^[0-9a-f]{64}$/`.
  - `send` to the receiver: headers `content-type: application/json`, `x-webhook-timestamp` = `String(sent_at)`, `x-webhook-signature-v2` = `sign(secret, ts, rawBody)`, no `x-webhook-signature`; `readWebhook(db).last.ok === true`.
  - « corps ignoré » : receiver answers 500 with `<html>secret</html>` → `error: "HTTP 500"`; receiver answers 200 with 100 kB of HTML → `ok: true`.
  - timeout (`timeoutMs: 100`) → `error` contains `"délai dépassé"`; `http://127.0.0.1:1` → `/^injoignable/`.
  - `alerts([opened, closed(reason "disabled")])` → exactly 1 POST; with `notify_close = 0`, `alerts([closed normal])` → 0 POST; disabled webhook → 0 POST; two `opened` events → 2 POSTs, each signature valid for its own body.
  - `readWebhook(db)` on a fresh db → `{ enabled: false, url: "", secret_set: false, notify_close: true, last: null }`; after a failed send, `readWebhook(db, { coarse: true }).last.error === COARSE_ERROR`, and `null` when the send succeeded.

- Produces: `GET /api/v1/webhook`, `PATCH /api/v1/webhook`, `POST /api/v1/webhook/test`, all returning `WebhookSettings`, coarse when `request.apiKeyId !== null`.
