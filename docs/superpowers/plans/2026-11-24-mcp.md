# Serveur MCP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose AQA to a Hermes agent as an MCP server at `/mcp` (Streamable HTTP, stateless, API key) with 9 typed tools, so the agent can read rooms, reports, history and alerts and manage the webhook.

**Architecture:** First move the logic now inlined in `routes/app.ts` handlers into `server/src/queries.ts`, so REST routes and MCP tools share it. Tool handlers live in `server/src/mcp/tools.ts` as plain functions over the db (unit-tested without MCP). `server/src/mcp/server.ts` registers them on an `McpServer` from the official SDK and mounts a stateless `StreamableHTTPServerTransport` on `POST /mcp`, behind key-only auth.

**Tech Stack:** Fastify 5, `@modelcontextprotocol/sdk` (latest 1.x, 1.32.2 at writing), zod 4, `node:sqlite`, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-24-agent-ia-design.md` (section « PR 3 — Serveur MCP » and « Doc Brancher Hermes »)

**Branch:** `feat-mcp` from `origin/DEV` **after `feat-cles-api` and `feat-webhook` are merged**. PR → `DEV`, title `feat(mcp): MCP server for agents`.

## Global Constraints

- Only new dependency: `@modelcontextprotocol/sdk`. Check with Context7 how this version takes zod schemas (zod 4 shapes vs `zod/v3`) before Task 4; the server already uses zod 4.
- Tool names and descriptions in English; values (zone words, labels, verdicts, takeaways) as AQA produces them, in French.
- Auth on `/mcp`: `Authorization: Bearer aqa_…` only (via `useKey`); a session cookie alone → 401. Rate limit 120 / min (`AGENT_RATE_LIMIT`).
- Timestamps in tool outputs: ISO 8601 with offset in the requested `tz` (default `cfg.AQA_TZ`, default `Europe/Paris`).
- No raw frames in any output; `get_history` ≤ 200 points (default 48).
- Webhook tools use the coarse result (`readWebhook(db, { coarse: true })`).
- `server/src/types.ts` stays runtime-free.

## Review Focus

- `room` given with different case or surrounding spaces (`"  salon "`) resolves; two boards with the same name → error listing both ids → test in Task 3.
- `get_day_report` on a DST day (`2026-03-29`, Europe/Paris, 23 h) covers exactly local midnight → next local midnight → test in Task 2.
- `get_day_report` for today before any measurement / a board with no data at all: a report with `measured_s: 0`, not a crash → test in Task 3.
- `get_history` over 400 days with `points: 200` → a clear tool error, not a 50 000-row answer → test in Task 3.
- An MCP `GET /mcp` (SSE probe some clients send) → 405, not the SPA HTML from the not-found handler → test in Task 4.

### Task 3: Tool handlers

**Files:**
- Create: `server/src/mcp/tools.ts`
- Modify: `server/src/webhook.ts` — extract the PATCH logic of `routes/app.ts` into `applyWebhookPatch(db: Db, input: unknown): { ok: true } | { error: string }` (same zod schema, same rules) and use it in the route
- Test: `server/test/mcp-tools.test.ts` (db from `openDb(":memory:")`, boards and frames inserted with `run`)

**Interfaces:**
- Consumes: `queries.ts` (Task 1), `localMidnight`, `addDays`, `withIsoTimes` (Task 2), `readRules`, `CATALOG`, `zonesOf`, `bandOf`, `soundDb`, `Webhook`, `readWebhook`, `testPayload`.
- Produces — each returns `ToolResult = { ok: true; data: unknown } | { ok: false; error: string }` and takes `ctx: { db: Db; webhook: Webhook; tz: string; publicUrl: string; now: () => number }`:
  - `resolveRoom(db, room: string): DeviceDbRow | string` (string = error message). Match id exactly, else `name.trim().toLocaleLowerCase("fr")`. Unknown → `Pièce inconnue : « x ». Pièces : Salon (aqa-…), Chambre (aqa-…).` Ambiguous → `Plusieurs pièces s'appellent « x » : aqa-…, aqa-…. Utilise l'id.`
  - `listRooms(ctx)` → `{ rooms: [{ id, name, online, last_seen_at, open_alerts, latest: { at, values: { co2: { value, unit: "ppm", zone }, pm25: {…"µg/m³"}, temp: {…"°C"}, hum: {…"%"}, snd: {…"dB" | "brut"} } } | null }] }`; `zone` = `bandOf(zonesOf(m, calibrated), v)?.word ?? null`; snd converted with `soundDb` when calibrated.
  - `dayReport(ctx, { room, date?, tz? })` — `date` defaults to today in `tz`; `from = localMidnight(date)`, `to = localMidnight(addDays(date, 1))`, `prevFrom = localMidnight(addDays(date, -1))`, `kind: "custom"`; output = `deviceReport(...)` **without `heatmap`**, plus `room: name`, `date`, through `withIsoTimes`. Future date → error.
  - `periodReport(ctx, { room, from, to, tz? })` (`YYYY-MM-DD`, `to` inclusive) — `to` exclusive bound = `localMidnight(addDays(to, 1))`; > 32 days → error `La période ne doit pas dépasser 32 jours.`; same shaping as `dayReport`.
  - `history(ctx, { room, metric, from, to, points? })` (ISO 8601 inputs, `points` 1–200, default 48) — step = smallest of `AGGREGATE_STEPS` with `ceil((to − from) / step) ≤ points`; none → error `Période trop longue pour ${points} points : réduis-la ou demande moins de détail.`; output `{ room, metric, unit, step_s, points: [{ at, avg }] }` (avg rounded like the app: 1 decimal for temp/hum, 0 otherwise).
  - `listAlerts(ctx, { room?, since?, limit? })` — all open alerts + ended ones with `started_at ≥ since` (default now − 24 h), newest first, `limit` default 50 max 200; rows `{ room, kind, label, started_at, ended_at, duration_s, start_value, peak_value, end_value, end_reason }` through `withIsoTimes`.
  - `alertRules(ctx)` → `readRules(db)` + `label`, `unit` from `CATALOG`.
  - `getWebhook(ctx)`, `setWebhook(ctx, input)` (→ `applyWebhookPatch`, then coarse read), `testWebhook(ctx)` (→ refuse like the REST route without URL/secret, else `webhook.send(testPayload(...))`, then coarse read).

  - `dayReport` on a board with frames on 2026-11-23 and 2026-11-24 (tz `UTC`, `now` fixed at 2026-11-24 12:00 UTC): `from` = `"2026-11-24T00:00:00+00:00"`, no `heatmap` key, `metrics` present, same `verdict` as `deviceReport` called directly with the same bounds; board with no frames → `ok: true`, `measured_s: 0`; `date: "2026-11-25"` → error.

  - `listAlerts` without `room` returns alerts of two boards; an alert ended 2 days ago is excluded by default and included with `since` 3 days ago.
