# Clés d'API — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an agent authenticate to AQA with a revocable API key (`Authorization: Bearer aqa_…`) on a fixed list of read routes, managed from the web UI.

**Architecture:** A new `api_keys` table stores sha256 hashes. The admin scope in `routes/app.ts` swaps `requireAdmin` for a `requireAdminOrKey(db)` preHandler that accepts a key **only** on routes flagged `config: { agent: true }`. Key management routes stay session-only. A global « Clés d'API » section in Réglages creates, lists and revokes keys.

**Tech Stack:** Fastify 5, `@fastify/jwt`, `@fastify/rate-limit`, `node:sqlite`, zod 4, React 19, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-24-agent-ia-design.md` (section « PR 1 — Clés d'API »)

**Branch:** `feat-cles-api` from `origin/DEV`, PR → `DEV`, title `feat(api): API keys for agents`.

## Global Constraints

- No new dependency.
- `server/src/types.ts` stays free of runtime code.
- UI copy in French, tutoiement; « instrument » style (reuse `Setting`, `Button`, `Field`, `Modal`, `useConfirm`, `useToast`).
- Key format: `aqa_` + `crypto.randomBytes(32).toString("base64url")`. Stored: `sha256Hex(key)` only. `prefix` = the 8 characters after `aqa_`.
- `last_used_at` written at most once per 60 s per key.
- Requests carrying `Bearer aqa_…` are rate-limited to **120 / minute** per IP.
- Routes open to keys — exactly: `GET /api/v1/devices`, `GET /api/v1/devices/:id`, `GET /api/v1/devices/:id/frames`, `GET /api/v1/devices/:id/frames/aggregate`, `GET /api/v1/devices/:id/report`, `GET /api/v1/devices/:id/alerts`, `GET /api/v1/devices/:id/events`, `GET /api/v1/alert-rules`. (The `/webhook` routes join in the webhook plan.) Everything else: session only.

## Review Focus

- A key sent with a wrong prefix or random string must get **401**, never 500 → test in Task 2.
- A key on a route **not** flagged must get 401 even though the key is valid (e.g. `POST /devices/:id/commands`, `POST /api-keys`, `PATCH /alert-rules/co2_high`, `GET /notify`) → test in Task 2.
- A request with **both** a valid cookie and a bad key on a flagged route: the cookie wins (the web app never sends a key, but don't let a stray header lock out the admin) → test in Task 2.
- Revoking a key while the agent is mid-use: the next request is 401 → test in Task 2.
- Name with only spaces → 422; 61 characters → 422 → test in Task 2.

- Modify: `server/src/types.ts` (add `ApiKey`)

**Interfaces:**
- Produces:
  - `interface ApiKey { id: number; name: string; prefix: string; created_at: number; last_used_at: number | null }` in `types.ts`
  - `createKey(db: Db, name: string, at?: number): { key: string; row: ApiKey }`
  - `listKeys(db: Db): ApiKey[]` (newest first)
  - `deleteKey(db: Db, id: number): boolean`
  - `useKey(db: Db, key: string, at?: number): number | null` — returns the key id or null; bumps `last_used_at` when it is null or ≤ `at − 60`
  - `const KEY_PREFIX = "aqa_"`

Migration (verbatim from spec):

```sql
CREATE TABLE api_keys (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  name         TEXT NOT NULL,
  prefix       TEXT NOT NULL,
  key_hash     TEXT NOT NULL UNIQUE,
  created_at   INTEGER NOT NULL,
  last_used_at INTEGER
);
```

### Task 2: Key auth on flagged routes + management API

**Files:**
- Modify: `server/src/auth.ts` (add `requireAdminOrKey`, Fastify type augmentation)
- Modify: `server/src/routes/app.ts` (scope hook, `config: { agent: true }` on the 8 routes, rate limit, `/api-keys` routes)
- Test: `server/test/apikeys-api.test.ts` (own `buildApp(cfg, { dataDir: ":memory:" })`, same `cfg` and login helper as `api.test.ts`)

**Interfaces:**
- Consumes: `useKey`, `createKey`, `listKeys`, `deleteKey` (Task 1)
- Produces:
  - `requireAdminOrKey(db: Db): preHandlerHookHandler`
  - Type augmentation in `auth.ts`:
    ```ts
    declare module "fastify" {
      interface FastifyContextConfig { agent?: boolean }
      interface FastifyRequest { apiKeyId: number | null }
    }
    ```
    plus `app.decorateRequest("apiKeyId", null)` in `buildApp`. The webhook plan reads `request.apiKeyId !== null` to know the caller is a key.
  - `const AGENT_RATE_LIMIT = { max: 120, timeWindow: "1 minute", allowList: (req) => !isKeyRequest(req) }` exported from `auth.ts`, where `isKeyRequest(req)` = `bearerToken(req)?.startsWith(KEY_PREFIX)`.
  - API: `GET /api/v1/api-keys` → `{ keys: ApiKey[] }`; `POST /api/v1/api-keys` ← `{ name }` (trimmed, 1–60) → 201 `{ ...ApiKey, key }`; `DELETE /api/v1/api-keys/:id` → 204 / 404.

`requireAdminOrKey` logic, in order: if the session cookie verifies → pass (`apiKeyId` stays null). Else if `request.routeOptions.config.agent` and the bearer token resolves through `useKey` → set `request.apiKeyId` and pass. Else 401 `{ error: "login required" }`.

Flag routes with the route options object, e.g. `scope.get("/api/v1/devices", { config: { agent: true }, onRequest: app.agentRateLimit }, handler)`, where `buildApp` does `app.decorate("agentRateLimit", app.rateLimit(AGENT_RATE_LIMIT))` once: one shared counter for every key route (a per-route `config.rateLimit` would give each route its own 120).

- [ ] **Step 1: Write the failing tests** (`describe("clés d'API")`):
  - session `POST /api-keys {name:"Hermes"}` → 201 with `key`; `GET /api-keys` → one key, no `key` field.
  - With `authorization: Bearer <key>` and no cookie: each of the 8 flagged routes (seed one device with `POST /devices` first) → not 401.
  - With the key, no cookie → **401**: `POST /devices/:id/commands {type:"status"}`, `POST /api-keys`, `GET /api-keys`, `PATCH /alert-rules/co2_high {enabled:false}`, `GET /notify`, `GET /firmware`, `DELETE /devices/:id`.
  - `Bearer aqa_nope`, `Bearer nimporte` → 401 on `GET /devices`.
  - Valid cookie + `Bearer aqa_nope` on `GET /devices` → 200.
  - `DELETE /api-keys/:id` → 204; the same key → 401; deleting again → 404.
  - `POST /api-keys {name:"   "}` and `{name: "x".repeat(61)}` → 422.
  - 121 requests with the key on `GET /alert-rules` within the test → the last is 429; the same 121 with the cookie only → none is 429.
