# Version mobile : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Sur téléphone, remplacer la vue web compressée par une app à 4 onglets en bas : Dashboard de jauges réordonnables, Alertes, Infos (lecture seule) et Graph plein écran en paysage. Pas de Carte ni de Réglages.

**Architecture :** Tout le code mobile vit dans `web/src/mobile/`. `Shell` (dans `App.tsx`) garde le poll des cartes et la carte choisie. Il rend `MobileShell` quand la requête « téléphone » est vraie, sinon la colonne et `DevicePage` comme aujourd'hui. Toute la logique sans rendu est dans des modules purs testés : routes mobiles, géométrie des jauges, ordre des jauges. Les composants réutilisent `metrics.ts`, `useSeries`, `ZoneChart` et `AlertJournal`. Aucun changement serveur.

**Tech Stack :** React 19, TypeScript 6, Vite 8, Vitest 5, uPlot (via `ZoneChart`). Aucune nouvelle dépendance.

**Spec :** `docs/superpowers/specs/2026-11-21-mobile-design.md`, à lire en entier avant chaque tâche. Maquette de référence : `.superpowers/brainstorm/438044-1795216249/content/mobile-v1.html` (fichier local, non commité).

## Global Constraints

- Mobile **uniquement sur téléphone** : `pointer: coarse` et petit côté de l'écran ≤ 720 px. Un ordinateur reste en version web à toute largeur. Le CSS `@media (max-width: 720px)` existant ne change pas.
- La vue ordinateur reste identique (aucun changement visible pour `Shell` web).
- UI et textes en français. Même tokens (`styles.css`), même police mono, clair/sombre. CSS mobile préfixé `.mb-`, placé en fin de `styles.css` sous un en-tête `/* ---- mobile */`.
- Couleur jamais seule : toujours un mot ou une valeur. Glyphes décoratifs en `aria-hidden`. Icônes SVG, pas d'emoji.
- Zones tactiles ≥ 44 × 44 px. `env(safe-area-inset-*)` respecté. `100dvh` pour le plein écran. Animations ≤ 200 ms, coupées par `prefers-reduced-motion`.
- Aucune nouvelle dépendance npm. Aucun changement dans `server/`.
- Pas d'attribution IA dans les commits (ni `Co-Authored-By`, ni « Generated with »).
- `npm test` et `npm run typecheck` (racine) puis `npm run build -w web` passent à la fin de chaque tâche.

## Review Focus

1. **Ordre de jauges enregistré abîmé ou ancien** (JSON invalide, mesure inconnue, doublon, mesure manquante) : on retombe sur un ordre valide des 5 mesures. Testé Task 2 (`readOrder`).
2. **Valeur hors bornes de la jauge** (CO₂ 2600, température −3) : le point est plafonné au bout de l'arc, le nombre affiché reste la vraie valeur. Testé Task 2 (`gaugeAngle plafonne`).
3. **Lien mobile ouvert sur ordinateur, ou lien web ouvert sur téléphone** (`#/graph/co2` sur PC, `#/reglages` sur téléphone) : on retombe sur `#/mesures` ou `#/dashboard`. Testé Task 1.
4. **Téléphone tourné en paysage** (largeur > 720 px) : reste en mobile. Testé Task 1 (`PHONE_QUERY`, contrôle de la chaîne), à vérifier à la main en Task 7.
5. **Plein écran ou verrouillage refusé** (iPhone, lien ouvert sans toucher) : aucune erreur visible, le graphe s'affiche sur toute la page. Vérifié à la main en Task 6. Les promesses rejetées sont attrapées.

**Files :**

- Produces :
  - `const GAUGE_START = 135`, `const GAUGE_SWEEP = 270` (degrés, 0 = droite, sens horaire, comme le SVG)
  - `const GAUGE_SCALE: Record<Metric, { min: number; max: number }>` : co2 400–2000, pm25 0–75, temp 10–35, hum 0–100, snd **30–90** (dB, calibré). Son non calibré : **0–4095** (amplitude), via `gaugeScale`.

  - `gaugeAngle(scale, v: number): number` : angle plafonné à `[GAUGE_START, GAUGE_START + GAUGE_SWEEP]`

  - `const ORDER_KEY = "aqa-gauge-order"`
  - `readOrder(store?): Metric[]`, `saveOrder(order: Metric[], store?): void`, `moveItem<T>(list: T[], from: number, to: number): T[]` (nouvelle liste)
